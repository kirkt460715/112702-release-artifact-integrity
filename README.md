# 场区离线升级包的完整性与组合上线审核

签名结果和摘要都是外部合成事实。项目没有签名材料、固件或实际设备控制。 资料均为本地合成记录。

以 Python 3.11.2 运行，无第三方依赖。`records/` 中的 `authorities`、`packages`、`field` 对应独立来源。每份材料是 JSON 对象数组，`id` 在同一来源内唯一。报告和观察的时间以各原始记录给出的字段为准。

```sh
python3 -m unittest -v
python3 records_view.py
python3 audit_view.py --summary
```

资料入口列出来源、记录标识及条数。通过 `--source` 指定来源，`--offset` 和 `--limit` 限定读取的位置与数量。`--records` 可指定同样结构的其他资料目录。

## 审计入口

`audit_view.py` 只读本地合成记录，按字段核对包的完整性、组合授权、现场进度与回退边界，不以文件名、版本号或介质标签作依据。工具不制作、传输或执行升级包。

判断依据：

- **摘要对应**：包清单摘要必须与签署摘要一致，且一个摘要只能对应一个包清单。现场登记的摘要必须能在包清单中找到。
- **组件标识**：同一组件标识不得在一个包内占据多个角色；更换包若沿用已撤销包的旧组件编号，视为混入旧组件。
- **签署范围**：角色必须在 `signed_scope` 内。`must_pair` 中的角色必须一起核准；组内任一角色未签署、无审批或证明不成立，整组不可用。`must_pair` 之外的角色可独立应用。
- **单件证明**：`proof-m` 这类记录只覆盖它自己声明的组件，不能顶替组合承诺；声明组件不在包内时不能覆盖对应角色。
- **发布方资格**：角色必须有该发布方的有效审批，审批的 `groups` 必须覆盖设备组。设备组只认记录字段；`field` 无 `group` 时按 `unit` 首段与已知审批组精确匹配，匹配不上即"无法核对"而非默认通过。
- **回退边界**：撤销报告命中摘要后，该包的旧审批不可复用；即使原审批仍在记录中，也不视为可用。

`--records` 可重复，用于追加重新开封后的新证据；同一来源内重复标识内容必须一致，冲突直接拒绝。`--at DAY` 按某个原始记录日评估撤销与审批是否已生效。`--section` 只输出 `findings`、`bundles`、`units`、`trusted`、`rollback`、`history` 之一。
